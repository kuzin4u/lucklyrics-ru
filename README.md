# lucklyrics.ru — сайт и коммерческие материалы

Репозиторий готов к заливке на GitHub и включению GitHub Pages. Ниже — что внутри, как задеплоить и как настроить DNS.

## Структура

```
index.html                                  ← редирект на lucklyrics-ru.html (нужен для GitHub Pages)
CNAME                                       ← домен lucklyrics.ru
lucklyrics-ru.html                          ← главная страница (индекс сайта)
semavi-landing.html                         ← лендинг SeMaVi (живой кейс)
reklamnyy-list-3-kanala.html                ← тарифы/КП/roadmap/вопросник — 5 каналов (4 вкладки в одном файле)
investitsionnyy-proekt.html                 ← инвестпроект, полная версия
listok-investproekt-s-podderzhkoy.html      ← инвестпроект, краткая версия с расходами на поддержку
whitelabel_roadmap.html                     ← интерактивный план + финмодель (аналитика Ozon/WB)
whitelabel_presentation.pptx                ← презентация к аналитике Ozon/WB (13 слайдов)
whitelabel_brief.docx                       ← бриф к аналитике Ozon/WB
kommercheskoe-predlozhenie.docx             ← КП: пакет Telegram + Сайт
roadmap-i-raschet-stoimosti.docx            ← roadmap: пакет Telegram + Сайт
voprosnik-tz.docx                           ← вопросник для ТЗ: пакет Telegram + Сайт
```

Все внутренние ссылки между файлами уже проставлены и проверены (см. раздел «Проверка ссылок» ниже) — при заливке в корень репозитория ничего дополнительно не нужно перелинковывать.

### Переименование файлов (транслитерация)

Три файла с кириллицей в имени переименованы в латиницу со схожим звучанием — все ссылки на них внутри репозитория обновлены автоматически:

| Было | Стало |
|---|---|
| `ИНВЕСТИЦИОННЫЙ-ПРОЕКТ.html` | `investitsionnyy-proekt.html` |
| `ЛИСТОК-ИНВЕСТПРОЕКТ-СПОДДЕРЖКОЙ.html` | `listok-investproekt-s-podderzhkoy.html` |
| `РЕКЛАМНЫЙ-ЛИСТ-3-КАНАЛА.html` | `reklamnyy-list-3-kanala.html` |

Причина: латинские имена корректно раскрываются в адресной строке и в расшаренных ссылках (кириллица в URL превращается в `%D0%98%D0%9D...` при копировании/рассылке).

## Деплой на GitHub Pages

1. Создайте новый репозиторий на GitHub (публичный — приватный тоже подойдёт, но нужен платный план для Pages).
2. Залейте содержимое этой папки **в корень** репозитория (не в подпапку) — например:
   ```
   git init
   git add .
   git commit -m "lucklyrics.ru sync"
   git branch -M main
   git remote add origin https://github.com/<ваш-аккаунт>/<репозиторий>.git
   git push -u origin main
   ```
3. В репозитории: **Settings → Pages**.
4. **Source**: Deploy from a branch → ветка `main`, папка `/ (root)`.
5. В поле **Custom domain** впишите `lucklyrics.ru` и сохраните — GitHub проверит файл `CNAME` (он уже в репозитории) и предложит включить **Enforce HTTPS** после того, как DNS будет настроен и сертификат выпустится.

## Настройка DNS на Reg.ru

Домен `lucklyrics.ru` уже зарегистрирован на Reg.ru. В панели DNS-записей домена добавьте:

**4 A-записи** для корневого домена (`@` / `lucklyrics.ru`) — все четыре нужны одновременно:
```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

**(опционально) CNAME для www**, если хотите, чтобы `www.lucklyrics.ru` тоже открывал сайт:
```
www  →  <ваш-github-аккаунт>.github.io
```

DNS может обновляться до 24 часов. Проверить можно так:
```
dig lucklyrics.ru +noall +answer
```
Когда все 4 IP видны в ответе — можно возвращаться в Settings → Pages и включать Enforce HTTPS.

## Известные пробелы (не исправлял, чтобы не выдумывать контент)

- `lucklyrics-ru.html` ссылается на `lucklyrics-en.html` и `lucklyrics-pt.html` (переключатель языка) — этих файлов ещё нет ни у меня, ни в этом репозитории. Ссылки останутся рабочими (не будут 404 внутри самого GitHub, просто ведут в никуда), пока страницы не появятся. По ранее зафиксированной структуре доменов EN-версия может жить на `lucklyrics.com`, а не на `.ru` — стоит решить до того, как эти ссылки увидит реальный посетитель.
- `.docx` / `.pptx` внутри GitHub Pages не открываются инлайн — браузер их скачает. Это ожидаемое поведение, ссылки на них рассчитаны именно на скачивание.

## Проверка ссылок

Все `href` между файлами репозитория проверены скриптом на момент сборки — рабочих ссылок 16 из 18, две недостающие (см. пункт выше) заведомо ожидаемы. Если будете переименовывать файлы после заливки — обязательно грепните репозиторий на старое имя, чтобы поправить все ссылки разом:
```
grep -rln "старое-имя-файла" *.html
```
