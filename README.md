### Переименование файлов (транслитерация)

Три файла с кириллицей в имени переименованы в латиницу со схожим звучанием — все ссылки на них внутри репозитория обновлены автоматически:

| Было | Стало |
|---|---|
| `ИНВЕСТИЦИОННЫЙ-ПРОЕКТ.html` | `investitsionnyy-proekt.html` |
| `ЛИСТОК-ИНВЕСТПРОЕКТ-СПОДДЕРЖКОЙ.html` | `listok-investproekt-s-podderzhkoy.html` |
| `РЕКЛАМНЫЙ-ЛИСТ-3-КАНАЛА.html` | `reklamnyy-list-3-kanala.html` |

Причина: латинские имена корректно раскрываются в адресной строке и в расшаренных ссылках (кириллица в URL превращается в `%D0%98%D0%9D...` при копировании/рассылке).

## Приём заявок (телефон + email)

Обе формы «Получить демо» (`lucklyrics-ru.html` и `semavi-landing.html`) собирают телефон и email и отправляют их на бэкенд — GitHub Pages статичен и сам ничего не хранит, поэтому нужен отдельный Google Apps Script.

**Два независимых бэкенда, намеренно не смешаны:**
- `API` (`__REVIEWS_API_URL__`) — существующая таблица заказов **Masa Madre** (хлеб на закваске). Используется только для чтения статистики (`loadStats()` → счётчики заказов/выручки на сайте). Этот файл её не трогает.
- `LEADS_API` (`__LEADS_API_URL__`) — **новая отдельная таблица** только для заявок с сайта LuckLyrics/KUZIN4U. Именно её создаёт и обслуживает `leads-backend.gs`.

Разделены специально: Masa Madre — торговля хлебом, LuckLyrics — IT-бизнес, разные области, не должны попадать в одну таблицу.

**Как это работает:**
- Телефон обязателен, email опционален (подсвечивается, если введён в неверном формате).
- При отправке форма POST'ит `{phone, email, ...}` на `LEADS_API`.
- Бэкенд складывает заявки в лист «Leads» новой таблицы — без ограничения по количеству. Google Таблицы спокойно держат сотни тысяч строк, искусственный потолок здесь не нужен.

**Установка:**
1. Создайте **новую** Google Таблицу — отдельную от таблицы заказов Masa Madre.
2. Расширения → Apps Script → вставьте содержимое `leads-backend.gs` целиком.
3. Развернуть → Новое развёртывание → Веб-приложение → доступ «Все».
4. Скопируйте URL (заканчивается на `/exec`).
5. В **обоих** `lucklyrics-ru.html` и `semavi-landing.html` замените `__LEADS_API_URL__` на этот URL (ищите `const LEADS_API = '__LEADS_API_URL__';`). `__REVIEWS_API_URL__` — отдельный плейсхолдер, не трогайте его при этой настройке, он по-прежнему указывает на таблицу Masa Madre.

## Деплой на GitHub Pages

1. Создайте новый репозиторий на GitHub (публичный — приватный тоже подойдёт, но нужен платный план для Pages).
2. Залейте содержимое этой папки **в корень** репозитория (не в подпапку) — например:
   ```
   git init
   git add .
   git commit -m "lucklyrics.ru sync"
   git branch -M main
   git remote add origin https://github.com/<ваш-аккаунт>/<репозиторий>.git
   git push -u origin main
   ```
3. В репозитории: **Settings → Pages**.
4. **Source**: Deploy from a branch → ветка `main`, папка `/ (root)`.
5. В поле **Custom domain** впишите `lucklyrics.ru` и сохраните — GitHub проверит файл `CNAME` (он уже в репозитории) и предложит включить **Enforce HTTPS** после того, как DNS будет настроен и сертификат выпустится.

## Настройка DNS на Reg.ru

Домен `lucklyrics.ru` уже зарегистрирован на Reg.ru. В панели DNS-записей домена добавьте:

**4 A-записи** для корневого домена (`@` / `lucklyrics.ru`) — все четыре нужны одновременно:
```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

**(опционально) CNAME для www**, если хотите, чтобы `www.lucklyrics.ru` тоже открывал сайт:
```
www  →  <ваш-github-аккаунт>.github.io
```

DNS может обновляться до 24 часов. Проверить можно так:
```
dig lucklyrics.ru +noall +answer
```
Когда все 4 IP видны в ответе — можно возвращаться в Settings → Pages и включать Enforce HTTPS.

## Известные пробелы

- **EN/PT переключатель** — исправлено: `lucklyrics-ru.html` (шапка + футер) теперь ведёт на `https://lucklyrics.com` вместо несуществующих локальных файлов `lucklyrics-en.html`/`lucklyrics-pt.html`. Ссылка «Português» тоже указывает на `lucklyrics.com` — по структуре доменов это одна англоязычная версия на США и Португалию сразу («то же на английском для США и Португалии»). Если для Португалии планируется отдельная страница на португальском — эту ссылку нужно будет поправить отдельно.
- `.docx` / `.pptx` внутри GitHub Pages не открываются инлайн — браузер их скачает. Это ожидаемое поведение, ссылки на них рассчитаны именно на скачивание.

## Проверка ссылок

Все `href` между файлами репозитория проверены скриптом на момент сборки — 16 из 16 локальных ссылок рабочие (EN/PT теперь ведут на внешний `lucklyrics.com`, не считаются как локальные файлы). Если будете переименовывать файлы после заливки — обязательно грепните репозиторий на старое имя, чтобы поправить все ссылки разом:
```
grep -rln "старое-имя-файла" *.html
```
